Alongside ordinary pages, this site hosts [notes](/notes/) and [writing](/writing/) posts. It took decades to settle into these two formats for time-stamped content, and is reflected in the content repository itself: the two types are stored separately and only writing posts have titles. They map very nicely to the [indieweb conventions](https://indieweb.org/post) of `note` and `article`.

But now, [finally](/2021/02/09/gemini.html), the repository is also expressed as [a Gemini capsule](gemini://hans.gerwitz.com/ “My capsule”). The web formats don’t work as well in Geminispace, where the conventions are for even short posts to have a title and hosting replies on your own capsule. So I’ve added a new content type, the `gempost`. 

As with the usual indieweb types, I can add gemposts via Micropub and they live as text files in the git repository which are rendered by Eleventy. Unlike the others, gemposts are only seen on the capsule and thus can only be visited via a `gemini:` URL using a gemproto browser or proxy.[^howto] Because they are in the content repository, they can appear as related posts or in search results, so we’ll see how well these two cyberspaces coexist!

[^howto]: The leading browser today is [Lagrange](https://gmi.skyjake.fi/lagrange/), and a popular proxy is Michael Lazar’s [Smolnet Portal](https://portal.mozz.us/gemini/).

I don’t trust myself to write posts in the Gemini file format, [Gemtext](https://geminiprotocol.net/docs/gemtext.gmi “Gemtext introduction”) and want a lot of existing content on my capsule. This means transforming Markdown into Gemtext and involves a lot more decisions than I expected; you can read about that on my capsule at <gemini://hans.gerwitz.com/capsule/gemtext/>.
